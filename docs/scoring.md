# 评分机制

本文档介绍 Paily 主服务如何根据节点的各种表现计算评分。评分范围约为 `0` 到 `1`，数值越高表示节点质量越好，用于在分发时优选节点，并用于节点列表的排序和等级展示。

## 数据来源

评分使用 Paily 测活后端复筛阶段上报的数据，包括详细延迟、抖动和可选下载速度。初筛结果只用于判断存活，不直接参与评分。测活后端如何采集这些数据，见其仓库的 `docs/check-pipeline.md`。

评分按「节点 + 测活后端 tag」分别计算。每个 tag 的评分独立保存，节点最终评分为所有大于 0 的 tag 评分的算术平均。这样可以在不同网络视角下分别衡量节点质量。

## 时间权重

评分只取该节点、该 tag 最近 20 条复筛记录，越新的记录权重越高。最新一条记录的序号为 `i = 0`，第 `i` 条记录的权重为 `alpha^i`：

```text
w_i = alpha^i
加权延迟 = Σ(w_i × 延迟_i) / Σw_i
加权抖动 = Σ(w_i × 抖动_i) / Σw_i
```

`alpha` 对应 `score_decay_alpha`，默认 `0.7`。它越接近 `1`，历史记录影响越大；越小，越侧重最近一次复筛。

若某条复筛记录不可达，其延迟按 `3000ms` 计，抖动按 `1000ms` 计，即按最差情况处理。

## 延迟分

先将加权延迟映射到 `0` 到 `1`，再通过对数曲线折算：

```text
latencyX = clamp(加权延迟 / 3000, 0, 1)
延迟分 = 1 - ln(1 + k × latencyX) / ln(1 + k)
```

`k` 对应 `score_latency_curve_k`，默认 `0.3`。使用对数曲线可避免低延迟区间的微小差距被放大为较大的分数差异。

## 稳定性分

稳定性依据加权抖动计算。抖动低于阈值时线性扣分，超过阈值后改用平方根曲线，使高抖动节点失分更快：

```text
jitterX = clamp(加权抖动 / 1000, 0, 1)
t = clamp(score_jitter_linear_threshold_ms / 1000, 0, 1)

当 jitterX <= t：稳定性分 = 1 - jitterX
否则：稳定性分 = (1 - t) × sqrt((1 - jitterX) / (1 - t))
```

阈值 `score_jitter_linear_threshold_ms` 默认为 `200ms`。

## 速度分与总分

速度只取最新一条复筛记录。先按 `score_weight_latency` 与 `score_weight_stability` 合成质量分，有测速数据时再按 `score_weight_speed` 混入速度分：

```text
speedX = clamp(speed_kbps / 163840, 0, 1)
速度分 = sqrt(speedX)

质量分 = 延迟分 × 延迟权重 + 稳定性分 × 稳定性权重
总分 = 质量分 × (1 - 速度权重) + 速度分 × 速度权重
```

默认质量权重为延迟 `0.7`、稳定性 `0.3`，速度的混合权重为 `0.55`。若上报结果中没有速度字段，表示本次未测速，速度不参与计算。最终分数保留 6 位小数。

## 参数与生效时间

上述参数均为动态配置，可在管理界面的「运行时配置」页面修改，默认值和完整清单见 [配置与 API](configuration-and-api.md)。

评分参数在内存中有最多约 1 分钟的缓存。修改参数后不会立即生效，需等待缓存过期，且该节点产生新的复筛结果后，评分才会更新。

## 等级

节点名称模板依据评分划分等级，阈值同样为动态配置：

| 等级 | 默认下限 |
| --- | ---: |
| A | `0.75` |
| B | `0.50` |
| C | `0.25` |
| D | 低于 C 的下限 |

等级仅用于展示和命名，不影响分发时的选节点权重。
