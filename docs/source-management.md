# 源库与来源管理

本文档介绍 Paily 主服务的源库：来源有哪几种、如何去重、如何维护拉取记录，以及来源在什么情况下会被自动裁掉。

## 工作流程

来源是节点进入平台的第一站。源提交器（Paicatch）或管理员把来源写入源库后，Paily Fetch 会周期性拉取启用中的来源，完成下载、解析和校验，再把节点上报给 Paily 主服务。Paily 主服务依据上报结果更新源的拉取记录，并据此判断来源是否仍然有效。

来源的管理操作在管理界面完成，但实际的抓取动作由 Paily Fetch 执行。订阅源内容的详细语法见 Paily Fetch 的 `docs/input-formats.md`。

## 来源类型

来源分为两类，按 `(type, content)` 去重，类型和内容相同的来源只保存一份。

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| `subscribe` | 订阅源 | 指向远程订阅地址，由 Paily Fetch 下载并解析，参与抓取失效判定。 |
| `node` | 节点 | 直接提供节点内容，无需下载，适用于无法自动更新的单节点。 |

一个去重后的节点可以关联多个来源。当某个来源不再提供该节点时，Paily 主服务只移除该来源的关联；只有当节点不再被任何来源引用时，才会删除节点及其测活历史。因此个别来源失效不会影响仍由其他来源提供的节点。

## 来源字段

| 字段 | 说明 |
| --- | --- |
| `identifier` | 来源标识，用于标记来源出处。 |
| `info` | 来源的补充说明。 |
| `content` | 来源内容。订阅源为地址或动态规则，节点内容。 |
| `status` | `active` 或 `dead`。 |
| `ignore_dead` | 为 `true` 时不再自动判死。 |
| `latest_fetch_node_count` | 最近一次成功抓取的节点数量，仅订阅源使用。 |

## 拉取记录与死源判定

源库为订阅源维护拉取记录，记录每次拉取的成功与否和节点数量（历史数量受限）。Paily Fetch 每次提交都会写入记录，Paily 主服务据此判断来源是否需要裁掉。

只有订阅源参与抓取失效判定。满足以下任一条件时，来源会被标记为 `dead`：

- 在 `fetch_dead_window_days` 窗口内存在抓取记录且全部失败，视为连续失败。
- 来源存在时间已超过窗口，但从未被抓取，或最后一次抓取早于窗口起点，视为长期沉默。

此外，Paily 主服务在每次测活结果提交时，还会检查来源对应节点的初筛历史。若节点长期没有存活记录，关联来源同样会被标记为 `dead`，判定窗口由 `node_dead_window_days` 控制。

已标记为 `dead` 的来源不会再发送给 Paily Fetch。若某个来源只是暂时不可用，但需要保留，可将 `ignore_dead` 设为 `true` 停止自动判定。

## 管理界面操作

管理界面的「来源管理」页面提供以下操作：

- 按类型、状态、标识符和描述筛选来源，或使用表达式搜索。
- 创建订阅源节点，填写内容、标识符与说明。
- 编辑来源内容与说明，删除来源。
- 切换 `ignore_dead`。
- 查看来源内容、抓取记录，以及该来源贡献的节点。
